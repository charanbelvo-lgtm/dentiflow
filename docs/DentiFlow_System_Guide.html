Doctor flow

Doctor signs in -> Dashboard -> Patients -> Aravind -> Clinical profile -> Dental Chart -> tooth 16 -> clinical finding -> Treatment Plan -> Invoice -> Payment -> Follow-up.

Patient flow

Patient signs in -> Patient Dashboard -> next appointment -> My Records -> Dental History -> Treatment Plan -> Prescription -> Bill. Patients can access only their own record.

Roles

Doctor
Patients, appointments, dental chart, clinical notes, prescriptions, treatment plans, invoices.
Patient
Own appointments, records, treatment plan, prescriptions, and bills.
Reception / Admin
Registration, appointments, queue, branches, staff, inventory, reports, settings, billing.
QA / Design
Route checks, responsive checks, loading and error states, accessibility, visual consistency.

Key routes

/ landing · /login authentication · /register signup · /dashboard dashboard · /patients patient directory · /clinical clinical workspace · /appointments visits · /queue queue · /staff doctor profiles · /treatment-plans care plans · /billing invoices · /api/health MySQL health.

Security and data

  • Passwords are hashed with Werkzeug.
  • MySQL remains the configured database.
  • Normal startup never drops tables.
  • Patient cross-record access returns HTTP 403.
  • Profile avatars are local cartoon assets.
  • Clinical seed data is demo-only and not a confirmed diagnosis.
